## 1. Executive Summary & Classification Scale

### 9-Tier Status Classification Scale
1. **`1. NOT STARTED`** — No implementation in code or schema (may have docs only).
2. **`2. DESIGNED`** — Specified in architecture/PRD docs, zero or stub code.
3. **`3. IN PROGRESS`** — Partial code exists, missing major slices of the requirement.
4. **`4. FRONTEND ONLY`** — UI exists without real backend/DB backing.
5. **`5. BACKEND ONLY`** — Backend API/DB/service exists, but zero UI invokes or renders it.
6. **`6. PARTIALLY FUNCTIONAL`** — End-to-end vertical slice works for core paths, but material PRD requirements, security controls, operational wiring, or UI surfaces remain missing.
7. **`7. IMPLEMENTED BUT UNTESTED`** — Substantially implemented across layers, but key runtime/DB integration tests (notably PostgreSQL 18 integration suites for Phases 6–10) have not been executed on a live DB host.
8. **`8. TESTED`** — End-to-end implementation with passing unit + integration tests in dev topology, yet still short of full production verification (e.g., load, RLS, live vendor QA, or legal sign-off).
9. **`9. VERIFIED COMPLETE`** — Meets all 12 criteria of the Feature Completion Rule (`AGENTS.md` §21) across UI, API, DB, validation, authz, error/loading/empty states, automated tests after final edit, docs, acceptance criteria, and zero fake/placeholder logic.

### Major Over-Claims Discovered in `MASTER_FEATURE_CHECKLIST.md`
The current `docs/MASTER_FEATURE_CHECKLIST.md` marks **23 features as `COMPLETED`**, violating `AGENTS.md` §21 (the 12-Point Rule) in **21 of those 23 cases**:
1. **`F-021` (AI Eval & Review Queue)** — Marked `COMPLETED` with `UI: DONE`, but **zero frontend pages** call or render `fetchAiReviewQueue`, `/api/v1/ai/evals/run`, or `/api/v1/ai/review-queue/{id}/decision`. It is **`5. BACKEND ONLY`**.
2. **`F-037` (AI/Voice Cost Telemetry)** — Marked `COMPLETED` with `UI: DONE`, but **zero frontend pages** call or render `fetchAdminAiCosts` (`GET /api/v1/admin/ai-costs`). It is **`5. BACKEND ONLY`**.
3. **`F-001` (Auth/Sessions/MFA)** — Marked `COMPLETED`, yet lacks email verification, password reset tokens, SSO (`auth_providers`), `devices` table, MFA recovery codes, encrypted `mfa_secret` (stored plaintext in `users.mfa_secret`), and stateless JWT revocation blocklist.
4. **`F-007` (Content Rights)** — Marked `COMPLETED` with `UI: DONE`, yet `/admin/page.tsx` only displays counts of sources/licenses—there is **no UI** to create sources/licenses or approve/reject legal review status.
5. **`F-008` (Canonical Question Bank)** — Marked `COMPLETED`, yet `/admin/page.tsx` only creates `"numerical"` questions (zero UI for MCQ, multi-correct, assertion-reason, matrix match, rubrics, hints, solutions, or PYQ verification) and `question_tags` table is missing.
6. **`F-009` (Excel Import Pipeline)** — Marked `COMPLETED`, yet runs synchronously inside FastAPI (blocking API worker), stores archives on local disk instead of S3, and has UI state/error bugs on `Commit Valid Rows` / `Rollback Batch` in `apps/web/src/app/admin/page.tsx:519-542`.
7. **`F-030` (Student Dashboard)** — Marked `COMPLETED`, yet `apps/web/src/app/dashboard/page.tsx` only renders Phase 1 stats; it never integrates study plans, due flashcards, homework status, weak concepts, mastery overview, exam readiness, or notifications.
8. **`F-026` & `F-034` (Adaptive Loop & Analytics)** — Marked `COMPLETED`, yet `apps/worker` is a Redis ping stub (`main.py`), so `outbox_events` are drained inline inside `GET /api/v1/analytics/student/overview` (`analytics/router.py:52`) instead of asynchronously! Institutional and platform analytics endpoints are absent.
9. **`F-017`, `F-018`, `F-019`, `F-022`, `F-023`, `F-024`** — Marked `COMPLETED`, yet AI tutor lacks SSE streaming, `knowledge_documents` has zero ingestion/browsing UI, `WS_MANAGER` is process-local memory (not horizontally scalable via Redis Pub/Sub), voice audio caches on local disk, and live Gemini/OpenAI/ElevenLabs provider runs have never been executed against real API keys.
